# KB Agent — Implementation Plan v1

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Replace Hermes-based KB pipeline layers A (ingestion), B (orchestration), D (synthesis) with a single Python process — Flask webhook + async consumer → SQLite state machine → mechanical steps + LLM synthesis → note → MinIO → Git push.

**Architecture:** Python from scratch, no agent frameworks. Flask (sync, main thread) + asyncio consumer (background thread). SQLite ×2 (agent.db + logs.db). Edgee for LLM gateway via httpx sync calls (NOT streaming — avoids known Hermes bugs). Full isolation: separate vault, MinIO bucket, cookies, config.

**Tech Stack:** Python 3.11+, Flask, sqlite3 (stdlib), httpx, asyncio, PyYAML, canonical scripts (diarize.py, transcribe.py from knowledge-base skill), yt-dlp, ffmpeg, mc (MinIO client).

## ⚠️ Open Questions & Assumptions (Decide Before Build)

These are things CONTEXT.md doesn't specify, or where I'm making assumptions you should validate.

### Q1: Edgee — Does it work for sync httpx calls?
- **CONTEXT.md says:** "Edgee as LLM gateway. Known Hermes HTTP/2 issues do not apply (custom agent uses standard httpx)."
- **Reality:** The 3 Edgee bugs were all streaming-related (HTTP/2 chunk headers, StreamReset, large-context timeout). Sync non-streaming calls MAY work. But we haven't tested.
- **My assumption for the plan:** I'm writing the LLM client as a swappable interface — `EdgeeClient` and `DeepSeekClient` both implement the same `call_llm(prompt, tools)` protocol. We default to Edgee, fall back to DeepSeek with a one-line config change. Compression is deferred (see Q3).
- **Risk:** If Edgee sync calls also fail, we lose a few hours of integration work that gets rewritten to DeepSeek direct. Mitigation: build the DeepSeek client FIRST (it's simpler, ~30 lines), then Edgee as a wrapper.

### Q2: Which models for which roles?
- **Not specified in CONTEXT.md.** My proposal:

| Role | Model | Rationale |
|------|-------|-----------|
| Synthesis (note writing) | `deepseek-v4-pro` | Same as current Hermes — proven quality |
| Boundary detection (chunking) | `deepseek-v4-pro` or `deepseek-chat` | Lightweight task, cheap model OK |
| Structural review (quality gate Tier 2) | `deepseek-chat` | Checks structure, not facts — cheap model fine |
| See Also (wikilinks) | `deepseek-chat` | Lightweight search → link task |

- **Tradeoff:** Using DeepSeek for everything is simpler (one API key, one client). Using a cheaper model for boundary/review saves ~80% on those calls but adds complexity. For v1, I'd use DeepSeek for everything — switch to cheaper models when cost becomes visible.

### Q3: Edgee compression — v1 or defer?
- **CONTEXT.md says:** "Compression tested empirically on 2-3 books before committing."
- **I couldn't find the test results** in any reference file. Unknown: what was tested, what method (summarization? prompt caching?), what fidelity loss.
- **My recommendation:** DEFER compression to post-v1. It's an optimization, not a requirement. The risk of compression degrading synthesis quality (especially for long books where every paragraph matters) is higher than the token cost savings. We can add it once the baseline quality is verified.
- **If you have the test results,** tell me and I'll incorporate them.

### Q4: Substack video download — in scope?
- **CONTEXT.md says:** "Detection works, but download is NOT fully solved. Mux CDN requires signed JWT token."
- The pipeline-substack.md reference shows the API at `/api/v1/video/upload/{id}/src?type=mp4` returns a 307 redirect to signed Mux URL. But CONTEXT.md says it's not solved.
- **My assumption:** Substack video is out of scope for v1. Detection will flag video posts as PAUSE with reason "Substack video download not implemented." The text pipeline works fine.

### Q5: Build order — incremental or full?
- **My strong recommendation:** Start with the simplest pipeline (web articles via Firecrawl) and add platforms one at a time. Why:
  1. Web articles = no cookies, no video, no diarization, no transcription. Just: Firecrawl → LLM → note → MinIO → Git.
  2. Verifies the entire architecture (Flask → consumer → SQLite → LLM → MinIO → Git) with the least risk.
  3. Each subsequent platform adds one new dimension (cookies, video download, diarization, etc.) — easy to isolate bugs.
- **Alternative:** Build the full detection model + all pipelines at once. Higher upfront cost, but you get everything. CONTEXT.md seems to assume this approach (it defines everything in detail).
- **My plan assumes incremental.** If you want full-build, I'll restructure.

## Success Criteria (What "Verified" Means)

For the overall system:
1. **End-to-end web article:** Submit a known Substack URL → note appears in kb-agent-vault → `git log` shows the commit → `mc ls minio/kb-agent-archive/articles/` shows the archived source → the note has ≥4 quotes, section-by-section analysis, and passes Tier 1 quality gates.
2. **End-to-end YouTube:** Submit a known YouTube URL → video downloaded → diarized → transcribed → note with speaker labels → MinIO archive → Git push. Note must have ≥3 concepts, ≥8 key points, density ≥100 chars/min.
3. **A/B comparison:** Process the same URL through Hermes KB pipeline AND KB Agent. Compare the two notes. The goal: KB Agent note is comparable or better. If it's worse, we know exactly why (LLM prompt? chunking? quality gate?).
4. **Crash recovery:** Kill the consumer mid-diarization. Restart. Consumer detects orphan step, resumes. No work lost.
5. **Cookie failure:** Submit a YouTube URL with invalid cookies. System PAUSEs with reason "cookies invalid — LOGIN_INFO missing." Does NOT create a stuck task.
6. **Dedup:** Submit the same URL twice. Second submission returns 200 with message "Already in vault — skipped."

```python
def init_db(db_path: Path, schema: str):
```

```python
import re

PLATFORM_PATTERNS = [
    (r'youtube\.com/watch|youtu\.be/|youtube\.com/shorts|m\.youtube\.com|youtube\.com/embed|music\.youtube\.com', 'youtube'),
    (r'threads\.(net|com)/@', 'threads'),

    (r'instagram\.com/p/', 'instagram_post'),
    (r'substack\.com/', 'substack'),
    (r'mega\.nz/', 'mega'),
    (r'\.epub$|\.pdf$|\.mobi$|\.azw3$', 'book'),
]

def detect_platform(url: str) -> str:
    for pattern, platform in PLATFORM_PATTERNS:
        if re.search(pattern, url):
            return platform
    return 'web'
```

```python
def create_task(conn, url: str, content_type: str, slug: str, steps: list[str]) -> str:
    task_id = str(uuid.uuid4())
    with conn:
        conn.execute(
            "INSERT INTO tasks (id, source_url, content_type, slug, status) VALUES (?, ?, ?, ?, 'pending')",
            (task_id, url, content_type, slug)
        )
        for i, step_name in enumerate(steps):
            conn.execute(
                "INSERT INTO task_steps (task_id, step_order, name, status) VALUES (?, ?, ?, 'pending')",
                (task_id, i, step_name)
            )
    return task_id

def claim_task(conn) -> dict | None:
    """Atomic claim — one query, no race condition."""
    with conn:
        row = conn.execute("""
            UPDATE tasks SET status = 'in_progress', updated_at = datetime('now')
            WHERE id = (SELECT id FROM tasks WHERE status = 'pending' LIMIT 1)
            RETURNING *
        """).fetchone()
    if row is None:
        return None
    return dict(row)

def get_next_step(conn, task_id: str) -> dict | None:
    row = conn.execute("""
        SELECT * FROM task_steps 
        WHERE task_id = ? AND status = 'pending'
        ORDER BY step_order LIMIT 1
    """, (task_id,)).fetchone()
    return dict(row) if row else None

def update_step(conn, step_id: int, status: str, output: str = None):
    with conn:
        conn.execute(
            "UPDATE task_steps SET status = ?, output = ?, finished_at = datetime('now') WHERE id = ?",
            (status, output, step_id)
        )

def complete_task(conn, task_id: str):
    with conn:
        conn.execute(
            "UPDATE tasks SET status = 'done', updated_at = datetime('now') WHERE id = ?",
            (task_id,)
        )
```

```python
async def step_firecrawl_extract(task: dict, config: Config) -> str:
    """Extract article via Firecrawl, save raw markdown to /tmp/."""
    url = task['source_url']
    slug = task['slug']
    
    proc = await asyncio.create_subprocess_exec(
        'curl', '-s', '--max-time', '60',
        config.firecrawl_url,
        '-H', 'Content-Type: application/json',
        '-d', json.dumps({'url': url, 'formats': ['markdown'], 'waitFor': 3000}),
        stdout=asyncio.subprocess.PIPE,
        stderr=asyncio.subprocess.PIPE
    )
    stdout, _ = await proc.communicate()
    
    data = json.loads(stdout)
    markdown = data['data']['markdown']
    
    raw_path = Path(f'/tmp/{slug}_raw.md')
    raw_path.write_text(markdown)
    
    if len(markdown) < 500:
        raise StepError("Content too short or 404", error_type='FAIL')
    
    log_to_db(task['id'], 'firecrawl_extract', f'Extracted {len(markdown)} chars')
    return str(raw_path)
```

#### Task 10: Pipeline — LLM synthesis step (web articles)

**Objective:** The core synthesis call. Loads template, calls LLM with tools (read_file, write_file, search_files).

**Key design decision:** The LLM gets `read_file` and `write_file` as tools. The Python orchestrator:
1. Writes the source to `/tmp/{slug}_raw.md`
2. Injects the template + quality rules into the system prompt
3. Calls LLM with tools
4. LLM reads source via `read_file`, writes note via `write_file` to vault
5. Python verifies the note was written

For content ≤50K tokens: single pass. For >50K tokens: progressive chunking (see Task 11).

```python
WEB_SYNTHESIS_PROMPT = """You are a knowledge base curator. Follow the deep treatment standard.

SOURCE: Read the file at {source_path} in its entirety.

TEMPLATE (output format):
---
date: {date}
source: {source_domain}
source_url: {source_url}
confidence: plausible
tags: [tag1, tag2]
---

# {title}

## Summary
3-5 sentences. The essential argument.

## Key Claims
≥4 specific claims with direct quotes (format >). Each with analysis.

## Section-by-Section Analysis
The dominant section. Break down the full arc of the source.

## Context
Who wrote this, why now, conflicts of interest.

## Critical Analysis
What's new vs restating? What's omitted? Keep shorter than thematic analysis.

## Nuances
Limitations, blind spots, tone.

## Reliability
Confidence level with justification.

QUALITY RULES:
- Key Claims ≥ 4, each with a direct > quote
- Section-by-Section must be the LONGEST section
- Target 10K-20K chars
- Read the ENTIRE source before writing
- Never push v1 — re-read and refine

Your tools: read_file (to read the source), write_file (to save the note).
"""

async def step_synthesize_web(task: dict, config: Config, llm: LLMClient) -> str:
    source_path = f'/tmp/{task["slug"]}_raw.md'
    note_path = f'{config.vault_path}/Knowledge base/articles/{task["slug"]}.md'
    
    prompt = WEB_SYNTHESIS_PROMPT.format(
        source_path=source_path,
        date=datetime.now().strftime('%Y-%m-%d'),
        source_domain=extract_domain(task['source_url']),
        source_url=task['source_url'],
        title=extract_title(source_path)
    )
    
    # LLM with tools: read_file + write_file + search_files (conditional: no web_search for articles)
    tools = [
        {"type": "function", "function": {
            "name": "read_file", 
            "description": "Read the source file",
            "parameters": {"type": "object", "properties": {"path": {"type": "string"}}}
        }},
        {"type": "function", "function": {
            "name": "write_file",
            "description": "Write the note to the vault",
            "parameters": {"type": "object", "properties": {"path": {"type": "string"}, "content": {"type": "string"}}}
        }},
        {"type": "function", "function": {
            "name": "search_files",
            "description": "Search the vault for related notes",
            "parameters": {"type": "object", "properties": {"pattern": {"type": "string"}}}
        }}
    ]
    
    response = llm.call(system_prompt=prompt, user_prompt=f"Process source at {source_path}", tools=tools)
    
    # Archive LLM call
    archive_llm_call(task['id'], 'synthesis', prompt, response.content, response.model, response.tokens_in, response.tokens_out)
    
    return note_path
```

#### Task 11: Chunking for large content

**Objective:** When source >50K tokens, split at semantic boundaries using boundary-detection LLM, synthesize progressively.

```python
async def step_synthesize_chunked(task: dict, config: Config, llm: LLMClient) -> str:
    source = Path(f'/tmp/{task["slug"]}_raw.md').read_text()
    
    if estimate_tokens(source) <= 50_000:
        return await step_synthesize_web(task, config, llm)  # Single pass
    
    # Boundary detection: cheap LLM call to find semantic split points
    boundaries = await find_semantic_boundaries(source, llm, target_size=50_000)
    
    # Progressive synthesis
    previous_note = ""
    for i, (start, end) in enumerate(boundaries):
        chunk = source[start:end]
        # Include 10K token overlap from previous chunk
        if i > 0:
            overlap_start = boundaries[i-1][1] - estimate_token_offset(source, 10_000)
            chunk = source[max(0, overlap_start):end]
        
        note = await synthesize_chunk(chunk, previous_note, task, config, llm, chunk_index=i, total=len(boundaries))
        previous_note = note
    
    # Final polish call
    final_note = await polish_note(previous_note, task, config, llm)
    return final_note
```

**Step 1:** Write `estimate_tokens()` — rough heuristic (~4 chars/token for English).
**Step 2:** Write `find_semantic_boundaries()` — calls a cheap LLM: "Here's the full text. Find natural boundaries every ~50K tokens. Return byte offsets."
**Step 3:** Write progressive synthesis loop.
**Step 4:** Test with a known long article (>100K chars).
**Step 5:** Commit.

```python
async def quality_gate_web(note_path: str, task: dict, config: Config, llm: LLMClient) -> bool:
    content = Path(note_path).read_text()
    
    # Tier 1 — Programmatic
    quote_count = content.count('\n> ')
    line_count = content.count('\n')
    size = len(content)
    
    failures = []
    if quote_count < config.article_min_quotes:
        failures.append(f"Only {quote_count} quotes, need ≥{config.article_min_quotes}")
    if size < config.article_min_size:
        failures.append(f"Size {size} chars, need ≥{config.article_min_size}")
    
    # Coverage check: does the note cover every section of the source?
    source = Path(f'/tmp/{task["slug"]}_raw.md').read_text()
    source_sections = re.findall(r'^## (.+)$', source, re.MULTILINE)
    note_sections = re.findall(r'^## (.+)$', content, re.MULTILINE)
    missing = set(source_sections) - set(note_sections)
    if missing:
        failures.append(f"Missing sections: {missing}")
    
    if failures:
        return False, failures
    
    # Tier 2 — Structural review (cheap LLM)
    review_prompt = f"""Review this note for structural quality:
    
    1. Is the dominant section actually dominant (longer than others)?
    2. Are any template sections empty or placeholder?
    3. Does the note feel rushed or incomplete?
    
    Note: {content[:5000]}
    
    Answer PASS or FAIL with reason."""

    review = llm.call(system_prompt="You are a quality reviewer.", user_prompt=review_prompt)
    
    if "FAIL" in review.content:
        return False, [review.content]
    
    return True, []
```

```python
    slug = task['slug']
    raw_path = f'/tmp/{slug}_raw.md'
    minio_path = f"minio/{config.minio_bucket}/articles/{slug}.md"

        stdout=asyncio.subprocess.PIPE, stderr=asyncio.subprocess.PIPE
    )
    await proc.wait()
    if proc.returncode != 0:
        raise StepError("MinIO upload failed", error_type='RETRY')
    
    # Verify
    proc = await asyncio.create_subprocess_exec(
        'mc', 'ls', minio_path,

    )
    stdout, _ = await proc.communicate()
    if slug not in stdout.decode():
        raise StepError("MinIO upload verification failed", error_type='RETRY')
    
    return f"http://minio.example.com/{config.minio_bucket}/articles/{slug}.md"
```

#### Task 14: Async consumer loop

**Objective:** The core loop that polls for tasks, executes pipeline steps, handles errors.

```python
class Consumer:
    def __init__(self, config: Config, db, llm: LLMClient):
        self.config = config
        self.db = db
        self.llm = llm
        self.video_semaphore = asyncio.BoundedSemaphore(config.video_semaphore)
        self.text_semaphore = asyncio.Semaphore(config.text_parallel)
        self.running = False
    
    async def start(self):
        self.running = True
        while self.running:
            task = claim_task(self.db.agent_conn)
            if task is None:
                await asyncio.sleep(5)
                continue
            
            if task['content_type'] in ('youtube', 'instagram_reel', 'mega_video'):
                async with self.video_semaphore:
                    await self.process_task(task)
            else:
                async with self.text_semaphore:
                    await self.process_task(task)
    
    async def process_task(self, task: dict):
        pipeline = get_pipeline(task['content_type'])
        
        while True:
            step = get_next_step(self.db.agent_conn, task['id'])
            if step is None:
                break  # All steps done
            
            try:
                update_step(self.db.agent_conn, step['id'], 'running')
                result = await pipeline.execute_step(step['name'], task, self.config, self.llm)
                update_step(self.db.agent_conn, step['id'], 'done', output=result)
            except StepError as e:
                if e.error_type == 'RETRY':
                    task['retries'] += 1
                    if task['retries'] >= self.config.max_retries:
                        pause_task(self.db.agent_conn, task['id'], str(e))
                        break
                    delay = self.config.retry_delays[min(task['retries']-1, len(self.config.retry_delays)-1)]
                    await asyncio.sleep(delay)
                    continue  # Retry same step
                elif e.error_type == 'PAUSE':
                    pause_task(self.db.agent_conn, task['id'], str(e))
                    break
                elif e.error_type == 'FAIL':
                    fail_task(self.db.agent_conn, task['id'], str(e))
                    break
        
        complete_task(self.db.agent_conn, task['id'])
    
    async def shutdown(self):
        self.running = False
        # Wait for running steps to finish
        # Kill children via PR_SET_PDEATHSIG
```

**Objective:** On startup: auto-create schema, recover orphan tasks, start consumer.

```python
def startup(config: Config):
    # 1. Init databases
    agent_conn = init_db(config.kb_agent_dir / 'agent.db', AGENT_SCHEMA)
    logs_conn = init_db(config.kb_agent_dir / 'logs.db', LOGS_SCHEMA)
    
    # 2. Recover orphan tasks
    orphans = agent_conn.execute(
        "SELECT * FROM tasks WHERE status = 'in_progress'"
    ).fetchall()
    
    for task in orphans:
        running_step = agent_conn.execute(
            "SELECT * FROM task_steps WHERE task_id = ? AND status = 'running' ORDER BY step_order LIMIT 1",
            (task['id'],)
        ).fetchone()
        
        if running_step:
            # Check if subprocess is still alive (for diarize, transcribe, yt-dlp)
            if is_subprocess_alive(running_step):
                log(f"Task {task['id']}: step '{running_step['name']}' still running — waiting")
                # Don't touch it — consumer will pick it up when step finishes
            else:
                log(f"Task {task['id']}: step '{running_step['name']}' died — re-running")
                agent_conn.execute(
                    "UPDATE task_steps SET status = 'pending' WHERE id = ?",
                    (running_step['id'],)
                )
    
    # 3. Start consumer
    consumer = Consumer(config, DB(agent_conn, logs_conn), get_llm_client(config))
    return consumer
```

## Tradeoffs

| Decision | Alternative | Why this choice |
|----------|-------------|-----------------|
| DeepSeek first, Edgee as wrapper | Edgee-only | Edgee untested for sync calls. DeepSeek is proven, works today. |
| Progressive chunking by LLM | Fixed-size chunking | Semantic boundaries → better note coherence. Fixed-size cuts mid-sentence. |
| No compression in v1 | Edgee compression | Untested. Risk of fidelity loss. Defer optimization. |
| Incremental platform build | Full build at once | Validates architecture with simplest case first. Reduces debugging surface. |
| Single Python process | Microservices (Flask + consumer separate) | "Minimum code that solves the problem." Single process = no IPC, no ports, no orchestration. |
| sqlite3 stdlib | SQLAlchemy / aiosqlite | Zero dependencies. Blocking calls are invisible next to 8h diarization. |
| Server-side HTML dashboard | React/Vue SPA | Zero JS dependencies. 2 routes. Tailscale-only — no CSS framework needed. |

## Risks

1. **Edgee might not work for sync calls either.** Mitigation: build DeepSeek client first, Edgee is optional wrapper. Fallback is one config line.
2. **LLM synthesis quality.** The whole point is better notes. If the LLM produces worse notes than Hermes workers, the project fails. Mitigation: A/B comparison (Task 28) catches this early.
3. **Chunking for large content.** Progressive synthesis is the least-proven piece. If chunk boundaries are bad, notes miss transitions. Mitigation: boundary LLM + overlap + final polish call. Test on known long-form content.
4. **Concurrency bugs.** BoundedSemaphore + async + SQLite WAL is simple but untested at scale. Mitigation: 5 hits/day means concurrency isn't stressed. Simple is better.
5. **Cookie management complexity.** YouTube, Instagram, Threads each need cookies, each can expire independently. Mitigation: pre-flight validation before every task. PAUSE with clear reason. Same pattern as current system.
